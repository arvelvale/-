# GitHub 自动提交规则

## 核心原则
**主动性** - 开发完成后主动提交，无需等待用户明确指令  
**完整性** - 确保 add → commit → push 三步完整执行  
**规范性** - 遵循提交信息规范

---

## 1. 自动提交触发条件

### ✅ 立即提交（自动执行）
- 完成完整功能模块开发
- 修复重要Bug（影响核心功能）
- 更新关键文档（需求、API文档）
- 完成代码重构
- 用户明确表示完成（"好了"、"完成了"）

### ❓ 询问后提交
- 功能部分完成，可能需要调整
- 代码质量检查发现问题
- 检测到未保存文件或冲突

### ⏸️ 无需提交
- 仅修改注释或格式
- 大型功能开发中间状态
- 小幅调试代码修改

---

## 2. 提交信息规范

### 格式模板

| 类型 | 格式 | 示例 |
|------|------|------|
| 新功能 | `feat: [描述]` | `feat: 添加用户登录功能` |
| Bug修复 | `fix: [描述]` | `fix: 修复数据加载失败问题` |
| 文档 | `docs: [描述]` | `docs: 更新API接口文档` |
| 样式 | `style: [描述]` | `style: 调整页面布局` |
| 重构 | `refactor: [描述]` | `refactor: 优化数据处理逻辑` |
| 测试 | `test: [描述]` | `test: 添加单元测试` |
| 配置 | `chore: [描述]` | `chore: 更新依赖版本` |

### 最佳实践
✅ 简洁明确，一句话说清楚  
✅ 使用动词开头  
✅ 避免模糊描述（"修改了一些东西"）  
❌ 不要只写 `update` 或 `fix bug`

---

## 3. 执行流程

```
开发完成
  ↓
检测完成标志
  ↓
生成提交信息
  ↓
git add .
  ↓
git commit -m "[信息]"
  ↓
git push
  ↓
反馈结果
```


---

## 4. Git 常用命令

```bash
git status              # 查看状态
git add .               # 添加所有更改
git commit -m "信息"    # 提交
git push                # 推送
git pull                # 拉取
git log --oneline       # 查看历史
```

---

## 5. 常见问题

| 问题 | 解决方案 |
|------|----------|
| 提交失败 | 检查网络、权限、解决冲突 |
| 提交信息错误 | `git commit --amend -m "新信息"` |
| 忘记添加文件 | `git add 文件` + `git commit --amend --no-edit` |

---

**记住**：开发完成后主动提交，保持版本控制连续性！
