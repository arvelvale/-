# 项目规划任务追踪规则

## 核心原则
**自动识别** - 根据提交代码自动识别完成的任务  
**实时更新** - 每次提交后立即更新规划文档  
**精确匹配** - 使用关键词和文件路径精确匹配  
**完整流程** - 识别 → 更新 → 提交 → 反馈

---

## 1. 任务完成判断

### 通用判断标准

| 任务类型 | 判断依据 | 示例 |
|---------|---------|------|
| 创建文件 | 文件存在 | `app.py` → "创建应用入口" |
| 实现功能 | 代码包含功能 | 包含认证逻辑 → "实现认证" |
| 配置项目 | 配置文件存在 | `config.py` → "配置数据库" |
| 编写文档 | 文档文件存在 | `README.md` → "编写README" |
| 数据库表 | 模型文件存在 | `models/user.py` → "创建用户表" |
| API接口 | 路由函数存在 | `@app.route('/login')` → "实现登录接口" |
| 前端页面 | 页面文件存在 | `pages/index.vue` → "实现首页" |
| 组件开发 | 组件文件存在 | `components/Header.vue` → "实现头部组件" |

---

## 2. 自动更新触发

### ✅ 立即更新（自动执行）
- 代码开发完成并提交后
- 数据库表创建后
- API接口实现后
- 页面/组件开发后
- 功能测试通过后

### ❓ 确认后更新
- 部分完成需返工的任务
- 功能实现但测试未通过

### 更新格式
```markdown
- [ ] 未完成任务
- [x] 已完成任务
```

---

## 3. 任务匹配策略

### 关键词匹配
根据任务描述关键词匹配代码文件：
- "搭建框架" → 检查 `app.py` 或 `main.py`
- "配置数据库" → 检查 `config.py` 或配置文件
- "创建XX表" → 检查 `models/xx.py`
- "实现XX接口" → 检查路由文件中的对应路由
- "实现XX页面" → 检查页面文件

### 模糊匹配
功能相似性匹配：
- "错误处理" → 检查错误处理中间件
- "日志记录" → 检查logging配置
- "请求封装" → 检查工具函数

---

## 4. 执行流程

```
1. 代码提交到GitHub
   ↓
2. 【自动】识别完成的任务
   - 分析提交的文件
   - 匹配规划中的任务
   ↓
3. 【自动】更新规划文档
   - 读取规划文件
   - 更新复选框状态
   ↓
4. 【自动】提交规划文档
   - git add 项目实施规划.md
   - git commit -m "docs: 更新任务状态"
   - git push
   ↓
5. 【反馈】生成进度报告
   - 完成任务列表
   - 整体进度百分比
```



---

## 5. 更新时机

| 场景 | 更新时机 | 方式 |
|-----|---------|------|
| 代码开发完成 | 提交后 | 自动 |
| 功能测试通过 | 测试后 | 自动 |
| 阶段性完成 | 阶段结束 | 自动 |
| 需确认的任务 | 用户确认后 | 手动 |

## 7. 特殊情况

```markdown

  - [x] 数据验证
  - [ ] 性能优化（待完成）
```

### 任务变更
```markdown
- [x] 实现XX功能（方案已调整）
  - 注：技术方案变更说明
```

### 任务取消
```markdown
- [x] ~~XX任务~~（已取消：原因说明）
```
